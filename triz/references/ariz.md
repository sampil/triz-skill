# ARIZ, condensed for working use

ARIZ (Algorithm of Inventive Problem Solving, АРИЗ) is the full procedure for hard problems.
The classic version, ARIZ-85V (АРИЗ-85В), has 9 parts and many sub-steps. This is a condensed
working version that keeps its logic. Use it in Deep mode. Keep a written trail of each step;
in the final answer show the trail only if the user asked for ARIZ.

## Part 1. Analyze the problem
1. State the **mini-problem**: system, its main function, the components, TC-1 and TC-2
   ("If ..., then + ..., but − ...") with minimal change to the system.
2. Identify the **conflicting pair**: the tool and the product (object). If the tool can be
   in two states, note both.
3. Represent TC-1 and TC-2 as schematic models (who acts on whom, with what result).
4. Choose the TC that better ensures the **main function** of the system. Proceed with it.
5. **Intensify** the conflict: push the tool's state to the extreme (infinitely large/small,
   zero/total). Extreme formulations often make the solution easier to see.
6. Write the **problem model**: conflicting pair, intensified conflict, and the task of finding
   an element X that would keep the useful action and eliminate the harmful one.
7. Try the **standards** (`su-field.md`) on the problem model. If one fits, go to Part 7.

## Part 2. Analyze the problem model
1. Define the **operating zone** (OZ): the space where the conflict happens.
2. Define the **operating time** (OT): the conflict time and the time before it.
3. Define the **substance-field resources** (SFR) available in the OZ during OT, first internal
   (tool, product), then external (environment), then supersystem. Cheap and free first.

## Part 3. Formulate the IFR and the physical contradiction
1. **IFR-1**: "X itself, without complicating the system and without harm, eliminates [harmful
   action] during OT within OZ, while keeping [useful action]."
2. Strengthen: replace X with a specific resource from Part 2 ("the [resource] itself ...").
3. **Macro PC**: "The OZ during OT must be [P] to perform [useful action] and must be [not-P]
   to prevent [harmful action]."
4. **Micro PC**: "The OZ must contain particles/elements of [type] (so that P), and must not
   contain them (so that not-P)."
5. **IFR-2**: "The OZ during OT must itself provide P and not-P."
6. Try the standards again with the sharpened PC.

## Part 4. Mobilize and use resources
Apply, in order, until an idea appears:
1. **Little smart people** modeling: imagine the OZ filled with tiny agents; how would they
   behave to deliver P and not-P? Then translate behavior into a mechanism.
2. **Step back from the IFR**: what would be needed if the desired result were already achieved?
3. Use a **mixture** of resources; use **voids** (empty space, empty time) mixed with resources.
4. Use **derived resources** (modified forms: decomposed, combined, changed state).
5. Use an **electric/informational field** instead of adding a substance.
6. Use a **field plus a field-sensitive additive**.

## Part 5. Apply the knowledge base
1. Apply **standards** to the PC.
2. Look for **analogous solved problems** with the same PC in other domains.
3. Apply the **separation principles** (`separation.md`).
4. Apply **physical, chemical and geometric effects** (by analogy: known mechanisms in software
   and business that switch a property between two states).

## Part 6. Change or replace the problem
If no solution yet:
1. Check whether a solution of a *different*, related problem would do (solve the problem one
   level up or down, or the inverse problem).
2. Reformulate: return to Part 1 with a different conflicting pair or TC.
3. Reconsider the initial problem statement: was it a symptom? Was the constraint real?

## Part 7. Analyze the solution
1. Check that the solution uses existing resources and adds as little as possible. Could an
   added element be replaced by a resource already present?
2. Estimate how close it is to the IFR.
3. Identify **secondary problems** the solution creates and whether they are easy to fix.

## Part 8. Apply the solution
1. How does the supersystem need to change to accept the solution?
2. Where else could the same solution or principle work?

## Part 9. Review the process
Compare the actual path to ARIZ; note any step that was decisive or misleading. (Optional; useful
when the user is learning TRIZ.)
